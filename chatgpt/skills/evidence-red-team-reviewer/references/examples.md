# 證據與紅隊情境範例

本檔供相關情境按需查閱。依 SKILL.md 已選模式、實際風險與使用者要求挑選段落；沒有相關問題時可明說未發現，不為數量或格式新增問題、產物或核准。範例中的工具、角色與專案條件不自動套用到當前任務。

# 使用範例一｜健康台灣深耕計畫

使用者：

「請對花東縱谷醫療生命線做 Evidence & Red Team Review。」

可能抽取主張：

1. 花東縱谷存在急症醫療可近性與照護連續性問題。
2. 三個節點協作可改善區域醫療韌性。
3. 玉里具備共同能力中心角色。
4. 鳳林可維持中北段急診可近性。
5. 臺東可改善長照機構急症支援與醫療整合。
6. 補助結束後三院可持續運作。

可能最強攻擊：

> 這是否只是將三院既有服務重新包裝成「生命線」，但沒有證據證明跨院協作會產生新的區域成果？

必要補強：

* 跨院流程
* 基線
* 區域共同 KPI
* 轉介與回轉資料
* 共同治理機制
* 補助前後的能力差異
* 經費如何產生跨院成果

# 使用範例二｜人才培育

原始主張：

「辦理教育訓練可改善偏鄉人才留任。」

Review：

* 訓練場次只能證明活動完成。
* 取得能力或認證才是中間成果。
* 職涯晉升、工作支持、薪酬與組織環境也會影響留任。
* 目前存在因果跳躍。

建議因果鏈：

> 訓練 → 能力評估 → 認證 → 分級授權／職涯發展 → 工作支持 → 留任意願與實際留任

並要求相應 KPI。

# 使用範例三｜導入 AI

原始主張：

「導入 AI 系統後，可提升照護品質與工作效率。」

Review：

證據不足，因為：

* 系統建置不等於使用。
* 使用不等於流程改善。
* 流程改善不一定等於臨床成果。
* 可能增加查核與資料輸入負擔。

建議改寫：

> 本計畫將導入 AI 輔助流程，並以使用率、任務完成時間、人工修正率、使用者負擔及照護品質指標評估其實際效益。

---

# 使用範例四｜預期結果寫成事實

原始內容：

「本計畫透過三院整合，有效降低轉診延遲與非必要住院。」

若計畫尚未執行，問題為：

* 將預期結果寫成既有事實。
* 「有效」需要正式成果資料。
* 「非必要住院」需要明確定義。

建議改寫：

> 本計畫預期透過三院共同轉介、穩定化與回轉機制，縮短轉診處理時間，並評估是否能降低可避免的急診及住院利用。

# 使用範例五｜POS 實作

主張：

「建立 Command Thread、兩個計畫書 Thread 與 Claude Canonical 後，即可提高一週內完成計畫書的效率。」

Review：

* 架構合理，但目前仍是工作假設。
* 建立 Thread 不等於協作成功。
* 需要用端到端 Pilot 驗證：

  * Handoff 是否可理解
  * Claude 是否正確更新
  * 是否只有一份正式版本
  * 主持人是否減少重複說明
  * 是否未增加額外維護負擔

建議先寫成：

> 本架構預期可降低跨 AI 與跨 Thread 的資訊遺失；將先以一個計畫書章節進行 Pilot，再依交班正確率、版本一致性與人工整合負擔評估是否擴大使用。
