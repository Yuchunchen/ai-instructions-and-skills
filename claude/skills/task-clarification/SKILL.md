# 任務釐清（Claude 版）

**版本：v1.0-claude｜2026-09-15**｜對應 ChatGPT 版 `task-clarification` v1.1；本版不重寫提問邏輯，而是組合 Claude 內建工具，價值在產出物與授權關卡。

## 啟動條件

只在使用者明確指名本 Skill，或明確要求先釐清、先問重要問題再執行時啟動。需求已明確的任務、一般修改、只引用或討論本 Skill，都不啟動。方向本身不清楚、答案會改變解法時，屬 `unknown-pass` 範圍。

## 釐清（用 AskUserQuestion）

- 先讀本次對話、附件與已提供資料；已知的不重問。
- 只問會實質改變目標、對象、範圍、交付、限制或驗收標準的問題。
- 一律用 AskUserQuestion 結構化提問：每輪最多 3 題，每題 2–4 個選項並標一個 Recommended 預設；使用者可選「其他」自由作答。
- 預設最多 2 輪。第 2 輪後仍有缺口，改列為待確認假設或建議預設，不再追問。
- 低影響且容易調整的細節不提問，直接列為建議預設。
- 不補造事實、數據、資源或承諾；推測標示為待確認。

## 產出：任務指令

資訊足夠（或資料原本就夠）時，停止追問，整理一份可直接複製的完整任務指令，依需要納入：

- 目標、必要背景與已確認決定
- 工作範圍、資料來源及必要查證工作
- 交付成果、格式與限制
- 可觀察的完成或驗收標準
- 待確認假設、建議預設與剩餘缺口（沒有就省略）

保留原始條件、證據狀態與授權範圍；不增加未同意的工作。

## 授權關卡

以 AskUserQuestion 請使用者選擇：「確認執行」／「修訂指令」／「只要指令，不執行」。未回覆、單純回答問題或要求修訂，都不視為同意執行。

確認執行後：

- 涉及檔案、程式或設定變更 → 進入 Plan mode，依指令產 plan，經核准再動手。
- 不涉及檔案變更 → 直接依指令完成，不再重複請示已同意事項。
- 多階段工作可視情況使用 `iterative-work-planner`；單一明確工作直接做。

使用者若明確變更流程、範圍或授權，以最新指示為準。

## 邊界

- 本 Skill 只產生任務指令與關卡，不取代 Plan mode 的實作計畫，也不重做 `unknown-pass` 的方向探索。
- 產出的任務指令是可攜帶的物件，可貼到其他 AI surface 或 Notion；貼出去不等於對方已接收或已執行。
