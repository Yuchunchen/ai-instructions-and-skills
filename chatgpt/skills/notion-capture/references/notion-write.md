# Notion 寫入與驗證

**版本：v1.1｜2026-10-11**

適用已授權寫入的 Knowledge Delta、討論決策與學習紀錄、設定快照、工作狀態／Checkpoint 或完整交班保存。只要草稿時不執行寫入。

## 1. 定位與讀取

- 已知頁面 ID／URL 時直接讀取，核對目標及其維護方式；不要先做全域搜尋。
- 位置不明才從「Workspace｜SSOT 總根」導航，在相關範圍按計畫、專案、主題或文件名稱查找。
- 不因名稱相似就假設正確。確有多個無法區分的候選時，最多提供三個並問最重要的位置問題。
- 已指定目標與方式就沿用；無法辨識可靠位置時先完成可貼入草稿，再問目的地。只有建立能力、父層位置／私人可見性及授權已確認時，才建立獨立私人頁，不以預設值假定私有。
- 新建前在目標父頁或相關搜尋結果確認無重複紀錄。已知 ID 的局部更新不必再全域搜尋。

## 2. 局部寫入

- 保留起草時讀取的基線（目標 ID、相關區塊與可取得的版本／時間）。實際寫入前重讀最新現況，三方比較「基線／現況／擬議修改」，只對已授權段落提出差異；預設新增或附加，不覆寫整頁，保留結構、歷史、子頁與他人變更。
- 現況與基線的差異若不碰本次段落，保留並在最新版上局部修改；同段內容、目標或 plan_revision 衝突時，不用舊稿覆蓋，暫停受影響段落、重新核對來源與裁定，其他獨立部分可繼續。版本／時間只能輔助比對，不能當作內容一致的證據。
- 同頁或同段落採單一寫入者協作約定：指明本次寫入者與範圍，其他協作者先交建議、交接後再寫。此約定不是 Notion 鎖、compare-and-swap 或原子性保證；兩次讀寫間仍可能競爭，不宣稱能防止所有覆寫。未能協調重疊寫入時暫停該段；回讀發現差異也先保留現況、查明原因，不盲目重放。
- 工作狀態更新沿用 plan_id／step_id，修訂 plan_revision 與差異紀錄，保留剩餘主線、分支 parent／return_to、採用分類與待同步操作；不得以最新分支摘要取代整體工作。
- 在已確認父頁下建立子頁，或在已授權的現有頁面追加有標記／日期的區塊；依使用者及該頁維護方式決定。
- 已授權的 Architecture／Registry／canonical 更新可由當次主責 AI 執行，只更新實際受影響區塊並保留歷史；不因正式頁面身分自動交 Claude。
- 沿用同一範圍的既有授權。只有新範圍、未授權外部動作、敏感資訊的新用途／可見性、不可逆風險或正式權責規定，才補相應核准。
- 明確要求學習紀錄時，已標示的假設、一次性觀察、未定案內容可按授權保存，不因此重複核准；不可升格為正式政策或一般事實。
- 不擅自刪除、搬移、封存頁面、改資料庫結構或新增不必要的資料庫／欄位／標籤。INDEX.md／CLAUDE.md 等檔案操作仍依專案規則及授權。
- 保存範圍不擴張為執行紀錄內的待辦、計畫、寄送訊息或發布。

## 3. 回讀與回報

- 回讀實際寫入的頁面／區塊，比對內容、位置、版本與重要資訊；多頁任務逐頁確認。
- 回報頁面名稱、可點擊連結、建立子頁／新增頁面／追加／局部更新方式，以及寫入和回讀狀態。
- 回傳成功但不能回讀時，明示「寫入回傳成功，內容尚未回讀驗證」，不說已驗證。
- 部分成功時分別記錄成功、失敗與未確認部分；保留可用成果，不說全部完成。
- 來源或工具不足時，提供可貼入的完整內容與解除條件；不假裝已讀取或寫入。

## 4. 結果不明與重試

- 明確未寫入：修正可恢復原因後重試尚未完成部分；權限／範圍未解時停止相依寫入。
- 逾時、連線中斷或回應不明：先以已知頁面／區塊 ID 回讀；未取得新頁 ID 時，以目標父頁、標題與本次內容識別比對。不得直接重試新增或追加。
- 已找到預期內容：視為已寫入，再完成回讀驗證，不建立第二份。
- 已確認不存在且可安全重試：只重試缺少部分；不回退或覆寫其他工作者的內容。
- 仍無法判定：停止可能造成重複的寫入，報「寫入結果未確認」，列可能受影響位置與下個核實步驟。無法回讀不等於沒有寫入。
- 交班給下一個 AI 時，帶入操作類型、目標、可用 ID、已知結果及回查方式，避免接手者當成未開始而重做。

Notion 連結不是交班全文；接手環境不能存取時仍須提供能開工的文字與必要來源。只更新本次授權且實際受影響的內容，不為填滿紀錄讀寫無關頁面。
