# Iterative Work Planner

**版本：v1.1.0｜2026-10-18**（補強情境式接續、分支回收與下一步選擇）

前版來源修訂：2026-09-06，未標語意版本；本版開始編版。

## 目的與使用邊界
將目標、範圍與主要做法已確認的多步驟工作，拆成能逐步完成的任務。基線可以是目前對話中已確認的摘要，不要求先製作另一份 Implementation Plan。
不為單一明確操作另建計畫；不因涉及多個工具或另一個 Skill 剛完成就自動啟動。若方向仍未定，只釐清會阻礙拆解的關鍵缺口，不重做整個設計。

已有可辨識的進行中計畫時，使用者說「繼續／回到主線／接下來呢」、分支收斂或新結果改變依賴，即執行下列接續流程；不必再要求使用者重述順序。無相關計畫的一般「繼續」不觸發本 Skill，多個可能主線無法判定時只確認要接哪個。

## 規劃粒度
- Light：近期少量工作，直接列必要任務、主要 Owner、實際依賴、成果與完成條件；不硬拆階段，也沒有最低任務數。
- Standard：涉及多階段或交接時，以成果分階段；細化近期任務，遠期保留概要。
- Extended：重大外部依賴、組織核准或持續營運時，再補維護責任、回復方式與正式檢查點。
只選當前需要的欄位；簡單任務可合併目的與行動。沒有核准點、交班或 Canonical 更新需求時，省略相關章節。

## 拆解原則
1. 保留已定案的目標、工具與範圍；每項任務產生可檢查成果。
2. 每項任務有一個主要 Owner。可另列協作者或 AI 支援；人類／明確系統的最終責任不得被 AI 支援角色取代。未知姓名不補造，標示待由 Decision Owner 指派。
3. 區分硬性依賴、可暫定前進的軟性依賴與外部依賴。指出誰解除、需要什麼、未解除時如何處理；無硬性依賴才可平行。
4. Checkpoint 是品質檢查，不自動成為 Approval Gate。已有授權應沿用；只有未被涵蓋的範圍、不可逆風險或正式權責規定才設新核准點。
5. 任務有可觀察的完成條件；實際存在階段才另定階段成果，並交代整體交付物的完成標準。
6. 近期成果完成後依實際差異調整下一輪；不為微小動作建立追蹤制度，也不建立無人維護的工作板。

## 主線、分支與可恢復進度

已有計畫時沿用主線與穩定步驟 ID，不因深入子題重新編號或遺失未完成步驟。需要中斷、分支或跨次接續時，讀 [planning-guide.md](references/planning-guide.md) 的「可恢復工作狀態」及「接續與下一步選擇」。

每次接續、分支收斂或改變計畫的結果出現時，依序執行：
1. **定位**：讀取可存取的現行計畫／checkpoint，確認主線、修訂版、目前步驟、分支父節點與返回點。不能假設看得到其他對話分支；缺少會影響決策的結果時索取最小摘要或來源，保留未確認狀態。
2. **回收與判定影響**：分支結論逐項標示已採用／已否決／待驗證；判定無變更、只補細節、需改依賴／順序／驗收、或需改目標／範圍。分支結束不等於父步驟完成；巢狀分支逐層返回。
3. **修訂主線**：依證據只更新受影響步驟與相依工作，保留原 ID、其他未完成工作及變更原因。允許插入、重排、替代或取消，不機械回到原字母順序；取消須有已確認決定或既有授權依據。前提改變使既有完成證據不再適用時，將受影響步驟改為待重驗／Review 或 Blocked，保留舊成果與失效原因，不沿用 Done。
4. **選下一步**：以修訂後依賴、證據、資源與授權選出一個可立即執行的具體行動及完成條件，不以最後一則訊息或最後分支當成新主線。無可執行步驟則交代阻塞、解除人與所需輸入；有不受影響的工作就繼續。
5. **留下接續點**：內容、依賴或狀態變更時遞增 plan_revision 並記差異；需中斷、分支返回或交接時保存 checkpoint，不為未改變工作狀態的微小操作新增紀錄。對使用者精簡交代「回到哪一步、順序是否改變及原因、下一步做什麼」。已授權執行就接著做；僅要求規劃時停在可執行計畫。

改變已確認目標、範圍或重要取捨時先由使用者裁定；不受影響任務繼續。接續先核對現行來源與外部操作結果，不以舊交班稿覆寫新版，也不重試結果不明的寫入。需要保存工作狀態到 Notion 時，明確區分工作狀態與學習紀錄，沿用指定位置與授權；未授權則只提供接續摘要，不自行寫入或建頁。

## 輸出與完成
交付能開始工作的最小充分計畫：規劃基線、近期任務與 Owner、必要依賴、完成標準，以及第一個可執行行動。只列影響行動的未知、阻塞與核准。整體完成標準涵蓋本次已授權的來源、帳號同步與適用的 Notion 工作狀態更新及回讀；未要求的目的地標示不適用，不擴大工作。分開回報來源已保存、帳號內容已回讀與實際 Runtime 驗證；任一必要部分受阻就報部分完成。
只要求規劃時，計畫可用即完成；不得把計畫寫成已執行。若外層任務也要求且已授權執行，規劃完成後接續工作、檢查成果、修正本次造成的失敗，直到外層完成條件達成或遇到實際阻塞，不停在第一版計畫要求重複批准。

## 失敗處理
若拆解發現會改變目標或架構的缺口，說明影響並暫停依賴該決定的任務；可獨立完成的工作繼續。外部資源不可用時指出解除條件與可行替代，不假裝任務 Ready 或 Done。
驗證依改動範圍選擇，不為文件小改要求完整系統測試；失敗後修正受影響工作，再檢查必要部分。

## 協作與呈現
Notion 日常維護預設 ChatGPT Work；Claude 可更新其主責工作已授權的頁面。程式工作預設考慮 Claude／Claude Code，使用者指定或既有 Codex 工作可直接延續。INDEX 與 SYSTEM.Exec 等檔案操作仍遵守適用專案指示。
只有真正換接手者才使用可用的 handoff Skill；名稱出現在文件中不代表該 Skill 已安裝。
使用繁體中文與台灣用語；預設使用精簡條列，需比較大量欄位或使用者指定時可用表格。
