# ChatGPT Thread Handoff

**版本：v1.5｜2026-10-11**

交付新討論串可獨立接續的工作脈絡，優先避免漏掉決策、理由與使用者修正。保留標記 `[ChatGPT-Handoff]`。

## 盤點與來源

先讀 [對話盤點與防遺漏核對](references/context-ledger.md)，依使用者指定範圍盤點可見對話，再按下一個任務產出。若本次已完成同規格的盤點，直接重用並補新增內容，不重做。

只使用可見或實際讀取的資訊；標示片段／摘要限制。不把 AI 建議當成使用者定案，不把計畫或工具嘗試當成完成。後來已有明確修正就沿用新版，舊版保留為已取代；未裁定矛盾才列待確認。

## 交班內容

按需要合併章節，不設最低行數，不以縮短篇幅犧牲重要資訊：
- **接續目標與背景**：要接手的任務、預期結果、必要前提。
- **目前狀態與成果**：已完成及驗證證據、進行中、尚未開始、受阻或結果不明的操作。
- **現行決策與理由**：使用者確認事項、重要替代方案、後來修正及應保留的術語／格式。
- **嘗試與結果**：影響下一步的做法、條件、結果及停止理由；未試、失敗、被否決不可混用。
- **授權與限制**：可修改範圍、已同意計畫、真正核准點；沿用適用的 Project 與專屬檔案規則。
- **來源與依賴**：資料位置、版本、已讀範圍，以及新 thread 的可存取性；必要的 Skill、App、附件與環境狀態只按實際證據記錄。
- **下一步與完成條件**：具體第一動作、必要核對、未解問題與實際阻塞。

有前次交班且已讀取時補「自上次交班的變化」。使用手機友善 Markdown 與使用者主要語言；中文採繁體中文、台灣用語。表格只有在精確對照有助理解時使用。

## 計畫與接手核對

要求 handoff plan 或多步接續需要順序／依賴時，讀 [接續計畫與接手核對](references/handoff-plan.md)，附在同一份交班稿；不自動新增另一個 skill 或重新要求核准。

即使是短交班，也交代接手者先核對即將使用／修改的必要現況；不重做已完成工作仍允許必要回讀。結果不明的外部操作先回查，不直接重複執行。

依本次工作改寫起始指令：

「請依本交班稿沿用現行決策、授權及計畫，核對即將使用或修改的必要現況，從『下一步』的具體第一項做到完成條件。不假設能取得未提供來源；只在會改變方向的重要未知、新增範圍、未授權動作或正式權責核准時回問。遇到阻塞，說明解除條件，繼續可獨立完成的部分。」

## 與 Notion 學習紀錄組合

- 只要求交班時，交付交班稿；不自動寫 Notion、建立新討論串或執行稿內任務。
- 同時要求保存討論決策、結論與學習歷程到 Notion 時，使用 `notion-capture` 的「討論決策與學習紀錄」模式，共用本次完整盤點，分別產生接續稿與學習紀錄；不可只將精簡交班稿當成學習紀錄的來源。
- 明確要求寫入且位置已確認時，沿用授權完成寫入與回讀。只要整理草稿時不寫入；Notion 部分受阻也先完成可交付的交班稿。
- 涉及設定／工作流變更時，按實際影響帶入變更物件、舊新差異、來源版本、UI 生效證據與待更新位置；無關時省略，Skill SOP 不複製到治理文件。

## 可恢復工作狀態

接續既有多步工作時，依 [接續計畫與接手核對](references/handoff-plan.md) 帶入穩定主線／步驟 ID、修訂版、分支父節點與返回點、已採用／已否決／待驗證結果、已驗證成果與未同步操作，以及具體下一步；不讓子題取代剩餘主線。接手先讀現行來源、處理差異，再依授權續作。

整體完成標準列入本次已授權的來源／帳號同步與適用的 Notion 工作狀態更新及回讀，逐項回報成功、失敗或未確認。保存內容不代表 Runtime 已使用；只要交班稿仍不執行稿內工作。

## 完成條件

依共通規格核對重要議題、修正、決策理由、嘗試、授權及來源均有去處，接手者不讀舊對話也能開始工作。稿件完成不等於新 thread 已建立、接手者已讀取或任務已執行；Notion 寫入與回讀狀態另列。
