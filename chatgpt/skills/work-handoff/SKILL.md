# Work Handoff Core

**版本：v1.3｜2026-10-10**

建立可脫離原討論使用的中立交班核心。保留標記 `[Work-Handoff-Core]`；完整性優先於縮短篇幅，不以品牌預設能力或修改權限。

## 路由

- 新 ChatGPT 討論串且只要一份交班：使用 `thread-handoff`；已確認由 Claude 接手：使用 `claude-handoff`，不先另產一份中立稿。
- 接手者未定時，先交付中立核心；只有目的地會實質影響資料存取、授權或成果時才詢問，不為選格式多問一輪。
- 交給 Codex、Gemini、人員或其他環境時，沿用本技能並交代已知環境；不假設共享檔案、工具或記憶。
- 只在原對話收斂、不交班時用 `conversation-review`。
- 只要保存決策與學習歷程到 Notion 時用 `notion-capture`；交班並保存時組合兩者，一次盤點、兩種用途，非完整聊天自動入庫。

## 盤點與防遺漏

讀 [對話盤點與防遺漏核對](references/context-ledger.md)，依指定範圍盤點重要議題、使用者修正、決策理由、替代方案、嘗試結果與狀態。已有同規格盤點時重用並補新增內容。

只依可見／已讀資料，不補造來源、理由、日期、版本或完成狀態。新裁定取代舊結論並標示歷史；無明確裁定的矛盾才保留待確認。AI 建議不等於使用者決策。

## 交班核心

依內容合併必要欄位：
- **目標與背景**：要接續什麼、預期成果與必要前提。
- **目前狀態**：成果及驗證、進行中、尚未開始、受阻或結果不明。
- **決策、修正與嘗試**：現行結論及理由、重要替代方案、已取代內容、實際嘗試與結果。
- **授權與限制**：可做／可修改範圍、既有計畫、真正核准點及專案規則。
- **來源與可存取性**：已包含的必要內容、可讀位置／版本、需取得或重傳的資料、必要工具及狀態。
- **下一步、重要未知與完成條件**：具體第一動作，阻塞與可獨立完成的部分。

有實讀前次交班時，補上其後變化。按使用者主要語言撰寫；中文用繁體中文與台灣用語，預設手機友善 Markdown。不要為填模板寫空節。

## 接續計畫

要求 handoff plan 或多步工作需排序／依賴／驗收時，讀 [接續計畫與接手核對](references/handoff-plan.md)，加在交班核心內。沿用既有計畫與授權，保留未定案方向，不自動執行計畫。

短交班也要交代必要現況核對：不重做已完成工作，但可回讀即將使用／修改的目標；結果不明的外部操作先核實，不重複新增。

## 組合保存與設定變更

- 同時要求寫入 Notion 學習紀錄時，交由 `notion-capture` 依同一完整盤點產生與保存；不只從精簡交班稿抽取。只有交班要求時不寫入。
- 涉及設定／工作流變更才列 Configuration / Workflow Delta：變更物件、舊新差異、來源／UI 驗證狀態與實際受影響位置。SOP 留在 Skill，不因版本變更自動擴大治理更新。
- 不把完整交班核心當成 Knowledge Delta；Notion 學習紀錄可保留探索歷程，正式知識另標狀態。

## 完成條件

完成共通規格的內容核對，接手者能獨立理解並從具體下一步開始。來源不足時列影響與取得方式；不以完整格式掩蓋未知。稿件完成不等於已送出、已建立討論串、已執行或已寫入外部系統。保留既有授權，不因交班重新核准所有步驟。
