# 來源、事實與確認

## 來源範圍

只用使用者指定的本場資料及明確補充。將逐字稿、筆記／草稿、會前背景分開辨認，會前預定議程不等於實際討論，草稿說法不自動凌駕原始來源。材料互相衝突且無明確更正時並列待確認；使用者明確確認的更正可用於新稿，但保留其更正來源。

為重要事實記下最短可追溯位置：檔名及段落、既有時間戳、頁碼、發言者或原文短句。不造時間戳、頁碼、出席身分。沒有段落 ID 的貼文可依序編 S1、S2，標為本次整理定位，不冒稱原始 ID。原文引句不可修字。

衍生紀錄可合併重複話語、精簡贅詞及省略無關的逐行標籤，但保留會改變意思的猶豫、條件與否定，以及重要發言的歸屬和可追溯位置。不要為統一人名而合併尚未確認是同一人的標籤。這些整理不回寫原始稿，引用仍保持原樣。

長稿應涵蓋所有可存取段落，再整合議題。只見片段或壓縮稿時，明示範圍；無法看到的全文不能列為已讀來源。保留末段撤回或改決議，不能只讀開頭生成正式全場紀錄。

## 事實分類

| 類別 | 認定與處理 |
| --- | --- |
| 現況／事實陳述 | 據來源記錄；未獨立驗證的當事人說法保留歸屬，不宣稱外部查證。 |
| 意見／原因說法 | 保留發言者與不確定程度；推測原因不升格為確認原因。 |
| 建議／提案 | 保留其尚未採納狀態，不能放進已定決議或承諾待辦。 |
| 決議 | 明確宣布通過、決定、裁示或有清楚採納記錄且未撤回，即保留；不另要求票數或已知主席才承認。詢問、期望、建議、沉默本身不是決議。 |
| 承諾／交辦 | 明確承諾或已決定執行的工作列待辦，即使責任、期限缺漏也保留工作。未獲接受的建議分工不能當已定主責。 |
| 已完成 | 來源或使用者明確更新為完成才記載。勾選、章節標題、期限已過、已承諾都不是完成證據。 |
| 模型分析建議 | 只在要求分析或需提出建議時另標「分析建議（非會議決議）」，不混入會議提案、決議或待辦總表。 |

保留否定、條件、重要異議、撤回、衝突及約數。條件式決議要連同條件呈現；反對某方案不等於反對其他工作。不同版本矛盾而來源未明示取代時，不自行選較新檔名作準。

## 缺漏與待辦

- 來源未提及欄位：填「未提供」。來源明說尚未決定：填「未定」。前者不能寫成當事人已決定暫不安排。
- 一個可獨立追蹤的工作一列，以 A01、A02 編號。相同決議與對應工作合併；不同責任或期限的子工作分列。只有決議沒有工作可用 D01，不能編造執行工作。
- 主責、協辦、期限、回報方式逐項對應；不能把相鄰工作或同案其他人的安排移過來。提案人不等於負責人。
- 模糊要求不能擅自擴充成已承諾的交付成果、工作範圍或驗收標準。已有承諾但內容不明時保留原有工作並列待確認；只有建議或詢問時不升格待辦。缺漏期限不主動補日期；使用者另要求工作拆解或期限建議時，放在「分析建議（非會議決議）」，不回填為既定安排。
- 狀態依來源填；已交辦但未談執行狀態，填「未提供」，可備註「已交辦」。明說待開始才填待開始，不自行寫進行中、已完成、逾期或取消。
- 建議日期與已定期限分開。相對日期只在會議日期與解讀都唯一確定時換算，保留原說法；不用今天、上傳日期、檔名猜會議日期。「下週五」有歧義就照錄待確認。錄音偏移不當作鐘點或散會時間。

## 疑義與更新

專名、人名、藥名、數字或辨識疑字以「[待確認：原文『…』，需人工核對]」保留；不猜正字、不補原文沒有的單位。Speaker ID 不當作正式名冊，也不推定人員身分。

疑義用 Q1、Q2 列出，含問題、原文短句／定位及待確認欄位。來源有明確安排就照錄，不能又泛問是否有期限。基本資料缺漏在基本欄位標示即可，除非影響結論，不機械產生十個 Q。

來源明說未定時，覆核題只詢問是否已有後續確定安排，不誘導使用者猜一個日期。使用者確認 Q1 不等於其他 Q 已確認；回覆沒有對應事實且會改變責任或決議時，先問清楚再更新。

公開稿不搬出敏感引文／可還原身分的來源名稱。為保留可追溯性，完整來源留在內部整理脈絡；公開正文僅用不洩漏資訊的來源描述。僅改稱甲／乙仍可能被認出時，省略不必要細節。
