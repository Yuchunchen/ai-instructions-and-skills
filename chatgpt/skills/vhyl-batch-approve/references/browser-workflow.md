# 瀏覽器操作及回查細節

本文件整理這個院內簽核系統已觀察到的 UI 行為，用來選擇可靠的下一步。每次仍以最新畫面及工具文件為準；歷史的分頁 ID、節點編號、每頁筆數及總筆數都不是常數。

## 工具與頁面辨識

- 使用已提供的 Browser 插件及其 JavaScript 工具操作使用者的 Chrome。依 Browser 技能初始化及讀取完整文件；需要接管分頁時，從最新分頁清單取得實際物件再接管。不得猜測分頁 ID 或使用失效的舊 handle。
- 查閱頁面可先使用目前選取分頁的上下文；要執行點擊時，再依當下 Browser 文件進行必要的 session 命名、分頁接管及狀態讀取。若當前環境不提供所需能力，回報缺少的能力，不用另一個瀏覽器代替使用者的 Chrome。
- 不用 shell、獨立 Playwright、CDP、直接 HTTP／POST、注入網站函式等路徑繞過 UI。透過當下文件允許的 DOM、定位器及可見介面操作即可。
- 目標 hostname：`am2.vhyl.gov.tw`。已觀察到待辦清單路徑 `/iftwf/WF9T08.php`，詳情路徑 `/iftwf/WF9T08A.php`。只用來核對現有頁面；不要憑空組出帶有工作階段參數的導覽網址。

## 已觀察到的清單結構

| 元件 | 已觀察到的值 | 用法 |
| --- | --- | --- |
| 待辦入口 | 待簽核表單(N) | 每批提交完成後重新點入，取得最新清單 |
| 其他佇列 | 代理簽核表單(N) | 不屬於預設授權範圍 |
| 清單 iframe | `#tabcontentA` | 先從當前 DOM 確認仍存在，再用 frame locator |
| 表單種類 | 全 部及各類表單 | 依使用者範圍，避免在局部篩選下宣稱全部清空 |
| 批次選擇按鈕 | 全部同意、全部清除 | 只有「全部同意」是本流程選取步驟 |
| 提交按鈕 | `確　定` | 含全形空白；依實際 accessible name 定位 |
| 正向選項 | 決　行、同　意 | 依各列實際選項核對 checked 狀態 |
| 未處理選項 | 暫不處理，觀察過 value `D` | 選到此項不能算同意 |
| 處理狀態 | 處理中，請稍候…、執行成功。 | 檢查狀態位置，不從申請理由猜測結果 |
| 空清單 | 待簽核數為 0、查無任何資料 | 重新載入後交叉核對 |

這是已觀察結構，不能跳過實際 DOM 核對。若名稱、frame 或表單種類已改變，以可見證據確認對應關係；無法確認就停止猜測。

## 選取與定位的實務問題

1. **點擊成功不一定有選取。** 曾發生一般 locator 點「全部同意」回傳成功，但 radio 沒有改變。先檢查實際 checked 狀態；確認未生效後，重新讀取 visible DOM，再用當下有效的 DOM CUA 節點點選。不要反覆使用同一失效定位器。
2. **節點 ID 只適用取得時的畫面。** DOM 變更、導覽、捲動或另一個查詢可能讓節點失效。每次使用節點 ID 點擊前緊接著取得 fresh visible DOM；不要把上一批或其他畫面的數字存成常數。
3. **讀取也可能改變捲動位置。** 某些 iframe locator 查詢曾把畫面移到中間；查詢後再次檢查目前 viewport。不要把畫面外或不同區域的控制誤認成原按鈕。
4. **大幅捲動可能逾時但已執行。** 先讀取新狀態，必要時小幅捲動或使用可見的返回頂端控制，不盲目重播逾時動作。
5. **長文字可能使列序列化分行。** 不要只以單行 `row` 文字的正規表示式取得表單號。從每列儲存格、各個 text 節點或完整快照取得識別碼，核對實際資料列數；不足就補讀，而非少算一筆後送出。

## 送出、回查與重試

每批只允許一個未核實的提交。可在本次執行記憶中保留下列欄位：

| 欄位 | 目的 |
| --- | --- |
| 批次識別碼集合與實際列數 | 核對選取、結果及避免重複計數 |
| 送出前待辦數 | 重新載入後核對變化 |
| 已按確定／尚未按確定 | 區分可重試選取與需要先回查的提交 |
| 每筆已觀察狀態 | 區分成功、處理中、失敗與未明 |
| 已核實完成的去重集合、批次數 | 提供有根據的進度及最終回報 |

點「確定」前先建立這份暫存狀態。使用短而有界的唯讀查詢檢查狀態；若一輪工具時間將用完，保留狀態，下一輪接續回查。不要用過長的阻塞等待，導致無法回報進度。

等待列消失的 `waitFor` 曾在實際已沒有匹配列時仍丟出錯誤。因此等待函式的錯誤本身不是送出失敗證據；重新讀取列文字、狀態與待辦清單。

上方待辦徽章曾有短暫延遲；所有列處理完後，先點「待簽核表單」重新載入，再檢查總數。例：送出前 100 筆，本批 20 筆，舊徽章仍顯示 81，而重新載入後為 80，這不構成需要再次送出的理由。

一般無新增案件時，可結合「本批逐筆成功／處理結束」、「重新載入後本批不在待辦」、「總數減少與本批一致」確認結果。若有新增案件、分頁或排序變化，不能只因本批不在第一頁就宣稱成功；用實際列狀態、既有成功證據及介面提供的搜尋／分頁能力確認。證據不足就保留未核實狀態，不重送、不把未知算完成。

錯誤判斷應針對提交提示或狀態欄。申請理由中出現「異常」「錯誤」等字眼，不能單獨視為簽核操作失敗。

## 分段執行與完成

- 每次工具呼叫可處理一至數個已核對的步驟或批次，避免大段不看結果的點擊迴圈。查到新狀態後才決定下一次寫入。
- 中斷後先恢復未核實批次；禁止由另一個代理同時接管並送出。
- 原清單為空或處理到空，都應確認已載入完成、範圍正確、待辦數為 0，且沒有資料列或顯示「查無任何資料」。
- 只回報實際完成數與批次。過往跑過的總筆數與批次數不能套用在新一輪。
- 不為驗證 skill 而再次送出真實表單。建立或修改 skill 時，使用合成頁面狀態檢查觸發、範圍、回查與停止條件；正式操作僅由當次使用者指令啟動。
