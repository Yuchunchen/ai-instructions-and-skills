# Threads 雷達

**版本：v2.0｜2026-10-31**（判定規則 v2：略過 → 值得試 → 留參考；留參考必填觸發條件）

**Claude 原生**：無 ChatGPT 對應版本。2026-10-31 於 claude.ai 帳號建立並儲存 v2，本檔自帳號版複製，僅加本段版本註記。

## 觸發

YC 在對話中丟 Threads 截圖或貼文連結（threads.net／threads.com），且沒有另外說明用途時啟動。只是問問題、討論貼文內容時不啟動。

## 存放位置（單一資料庫原則）

- 一般貼文 → Notion「🧵 Threads 收藏庫」（位於 SYSTEM｜檔案系統與工作流；data source `collection://2bac1b05-fcff-4380-8d2d-b565308cbe6d`）
- 內容主體是可重複使用的單一 Prompt →「🗂️ Prompt 收藏庫」（`collection://842b3260-8797-49de-a304-a9a29c3c9d2b`），照該庫既有頁面骨架。
- 只附 repo、沒有 Prompt 原文的「Prompt 集合」→ Threads 收藏庫。
- 不另建資料庫、artifact 或 repo 來存放。
- 分不出是哪一類時問 YC。

## 流程

1. **分組**：同一則貼文的多張截圖合併成一筆。先用 SQL 查收藏庫有沒有同作者、同主題的紀錄；重複的略過並告知，補充的就更新原頁。
2. **查證**：貼文提到的 repo、網站、文章，用 WebFetch 或 WebSearch 去看原始來源。截圖裡的連結通常被截斷，就用連結卡片上的 repo 名稱或關鍵字搜尋找到原頁。一眼就能判為略過的（娛樂展示、個人心得）可以不查。Threads 頁面本身常有登入牆，抓不到就以截圖為準。查證要看：
   - 原始來源是否屬實，跟貼文說法有沒有出入
   - 作者或維護者是否可信、還有沒有在維護
   - 授權能不能用
   - 跟院內限制相不相容（封閉網路、病人資料不外流）
3. **判定有料程度**：照下方「判定規則 v2」。
4. **寫入**：
   - 值得試／留參考：完整頁面，內文依序為截圖 → 原文轉錄 → 與我工作的關聯（Claude 判斷）→ 來源
   - 略過：只存一行，即標題、作者、一句話摘要，略過原因寫進「查證結果」；不轉錄全文、不上傳截圖
5. **驗收**：用 SQL 查詢確認——每筆都有有料程度；值得試都有建議行動；留參考都有觸發條件；略過都有略過原因；作者與截圖數正確。

## 判定規則 v2

由上往下判，符合第一條就停。

**1. 略過**：符合以下任一條
- 對不上 RESEARCH、HOSPITAL、LECTURE、SYSTEM 任何一軸
- 純娛樂展示、個人使用心得、沒有可驗證的內容
- 查證後發現原始來源跟貼文說法不符，或已停止維護、沒有可用授權
- 收藏庫已經有同樣的內容
- 在院內的限制下用不了（例如資料一定要上雲、要把內網服務開到公網），而且也沒有院外用途

**2. 值得試**：以下三條同時符合
- 對得上任何一軸（不限主戰場）
- 現在就有具體對象可以用，能指名是哪個專案、系統或文件
- 第一步成本低：幾小時內能試，不用採購，也不用等別人配合

→「建議行動」必填，寫到具體的下一步，開頭標註（主戰場）或（非主戰場）。主戰場以 Notion「🗺️ Strategic Map」的本季主戰場為準；Strategic Map 超過一個月沒更新時，在回報裡提醒。

**3. 留參考**：其餘有價值的

→「觸發條件」必填，寫具體事件，例如「寫 Paper 2 方法時」「地端平台要開放外部存取時」。不能寫「有需要時」。寫不出具體事件時，先寫推測的時機並標明「（推測）」。

判定是 Claude 的初判，YC 可以直接在 Notion 改。

## 欄位

標題、截圖（檔案）、摘要（3 行內）、主題標籤（日常中文詞，從內容長出來；新增選項時要列出全部既有選項）、相關主線（RESEARCH／HOSPITAL／LECTURE／SYSTEM／無直接關聯）、作者、發文日期、來源網址、狀態（已整理／待補資料／已讀用）、有料程度、查證結果、建議行動、觸發條件。

## 寫作規則

- 原文逐字轉錄：看不清楚的標〔無法辨識〕，被遮住的標〔截斷〕，不自己補字。核心內容被遮住時，狀態設為待補資料。
- 截圖上沒有的資訊留空，不猜。把相對時間（例如「2天」）換算成日期時，標「約」並寫出依據。
- 「與我工作的關聯」「有料程度」「建議行動」「觸發條件」都是 Claude 的判斷，頁面上要標明。
- 作者帳號、不完整的網域、localhost 等字串用程式碼格式包起來，避免 Notion 自動轉成錯誤連結。
- 作者介紹自家產品時，在關聯段註明「不是第三方評測」；涉及程式碼或資料上雲的工具，提醒院內資料外流規定。

## Notion 操作注意

- 圖片上傳：用 notion-create-file-upload 取得上傳網址 → 用 curl 以 multipart POST 送出檔案 → 內文寫 `<image source="file-upload://ID" />`。同一張截圖要放進兩筆紀錄時，各自上傳一次。
- 「截圖」欄位：notion-create-pages 不接受 file_upload，要在建立頁面後另外用 update_properties 寫入。
- update_content 會忽略同一個呼叫裡一起送的 properties；欄位一律用 update_properties 單獨送。

## 回報格式

- 用表格列出：貼文、有料程度，以及建議行動（值得試）或觸發條件（留參考）。
- 接著列出沒收的內容：截圖邊緣露出的其他貼文、串文缺的部分，讓 YC 決定要不要補。
- 手機閱讀為主，精簡；不重複頁面上已經寫的內容。
