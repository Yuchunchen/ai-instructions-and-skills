# Notion Knowledge Capture

**版本：v1.2｜2026-09-06**

將值得長期保存的知識安全地沉澱到 Notion。Notion 是長期知識與 Governance／Architecture／Registry Canonical 的保存層；AI Instructions／Skills 原文以 GitHub 為 Source Canonical，產品設定介面的 Runtime 狀態另行驗證。

日常 Notion 維護預設由 ChatGPT Work 承接；Claude 完成其主責的長文件或程式工作時，也可更新授權範圍內的對應頁面。每次更新由當次主責 AI 完成，接手者先讀最新版，不以 AI 品牌決定內容是否為正式版本。

## 基本原則

- 只使用目前可見對話、使用者提供資料，以及工具實際讀取到的 Notion 內容。
- 不假裝已讀取或已寫入 Notion。
- 完整聊天、完整交班稿與 Knowledge Delta 是不同物件。
- 只保存已整理、可重複使用且會影響後續理解或工作的方法與變化。
- 寫入前 read-first。
- 預設只新增或附加，不覆寫既有內容。
- 只修改已授權的頁面或區塊，保留既有結構、歷史與子頁；一般新增內容可使用 `[ChatGPT]` 區塊或安全的子頁／獨立頁。
- 已授權的 Notion Architecture、Registry 或 canonical 更新可由當次主責 AI 執行，遵守目標頁的維護方式；不自行擴張修改範圍。INDEX.md、CLAUDE.md 的檔案操作及資料庫結構變更仍依適用專案指示與獨立授權。
- 不刪除、搬移、封存頁面，也不建立不必要的資料庫、欄位或標籤。
- 資訊矛盾或未定案時，標示狀態，不把它寫成正式結論。
- 使用使用者主要語言；中文時使用繁體中文與台灣用語。

## 值得保存的內容

優先保存：

- 已確認的新決策及理由
- 改變 AI 分工或工作流程的重要發現
- 被修正或推翻的重要舊假設
- 經多次使用或驗證的可重複方法
- 影響 Project Instructions、教學、研究或制度的重要限制
- 新的風險、驗證方法、回退方案或版本差異
- 已形成並可跨討論串使用的工作流

預設不保存：

- 全部聊天原文
- 寒暄或重複內容
- 單次語氣差異
- 未控制變因的一次性觀察
- 尚未整理的腦力激盪
- 臨時 Todo 或短期進度
- 無日期、版本或來源的截圖結論
- 只具新聞性但不影響工作流程的更新

## 版本化設定快照

當內容是 About Me、Global Custom Instructions、Project Instructions、Skills 或 AI surface 設定時：

- 保存**完整文字或可驗證版本摘要**、日期、來源與 UI 生效狀態。
- 明確區分「已在 UI 生效」「建議版本」「待確認」「已退役」。
- 新版本建立新快照或在既有快照中追加 dated block；不要覆蓋舊版本。
- Skills 只保存名稱、版本、用途、觸發條件、依賴與變更摘要；完整 SOP 留在 Skill 本體，不複製到 Architecture。
- 若涉及 Architecture、Setup Log、instruction snapshot 或 canonical，形成 Configuration Delta，由當次已授權主責 AI 更新實際受影響頁面並回讀；只有確實需要 Claude 接手時才產生 Claude handoff。
- 不因單次產品 UI 出現就推論所有帳號、平台或方案皆一致；保存觀察日期與裝置／平台。

## 處理流程

### 1. 判斷請求

- 若使用者只要求「整理 Knowledge Delta」，先產生草稿，不寫入。
- 若使用者明確說「存到／寫入 Notion」，使用可用的 Notion App 或工具執行。
- 若工具不可用，產生可直接貼入的 Notion 區塊，並明確說明尚未寫入。

### 2. 抽取 Knowledge Delta

區分：

- 已確認
- 暫定
- 待驗證
- 已推翻
- 建議
- 不應進入 canonical

只選擇真正具有長期價值的內容。

### 3. 找寫入位置

- 使用者已指定頁面時，先搜尋並讀取該頁。
- 使用者未指定時，依計畫、專案、主題、單位與文件名稱搜尋相關頁。
- 最多提出三個可靠候選。
- 使用者已指定頁面與寫入方式時沿用；只有放置方式尚未確認且會影響既有內容或治理時，才詢問要建立子頁或附加區塊。
- 多個同名或用途不同的頁面無法判斷時，一次只問一個最重要問題。
- 找不到安全位置時，建立獨立私人頁面；不要猜測 canonical 位置。

### 4. 安全寫入

可直接執行：

- 在使用者指定且已讀取的計畫頁下建立子頁
- 建立獨立私人頁
- 在非 canonical 頁面尾端附加明確的 `[ChatGPT]` Knowledge Delta 區塊
- 已有明確授權與範圍的 Notion canonical 更新：先讀現況，依適用維護規則局部修改或追加 dated patch，完成後回讀；不因正式頁面的身分自動轉交 Claude

下列工作若尚未獲得涵蓋該內容與範圍的授權，必須先取得確認；已確認的同一範圍不重複核准：

- 直接修改計畫主頁的重要內容
- 同時寫入多個頁面
- 內容含敏感、矛盾或未定案資訊
- 可能影響正式決策、制度或現行版本

不得直接執行：

- 覆寫整頁
- 修改資料庫結構
- 刪除、搬移或封存頁面
- 未授權的 Architecture、Registry 或 canonical 修改，以及本 Skill 範圍外的 INDEX.md／CLAUDE.md 檔案操作

超出授權範圍時先準備變更內容、影響與必要核准，不因涉及 Notion 就一律交給 Claude。若使用者指定 Claude 接手，再產生 `[ChatGPT-Delta｜for Claude]`。

### 5. 驗證與回報

寫入完成後：

1. 重新讀取已寫入的頁面或區塊，確認內容與預期相符；無法回讀時明示「寫入回傳成功，內容尚未回讀驗證」。
2. 回報頁面名稱、位置、寫入方式與狀態。
3. 提供可點擊的 Notion 連結。
4. 說明是否建立新頁、建立子頁或附加內容。
5. 若失敗，說明失敗步驟、是否有部分寫入，以及是否修改任何既有內容。
6. 不得在工具失敗時聲稱已完成。

## Knowledge Delta 固定格式

[ChatGPT｜Knowledge Delta]

### 1. 主題
說明這項知識屬於哪個計畫、軸或工作流。

### 2. 建立日期與來源
列出日期、來源對話／檔案／頁面，以及來源可存取性。

### 3. 變更類型
從下列選擇：
- 新決策
- 新發現
- 舊結論修正
- 工作流變更
- AI 分工變更
- 教學內容修正
- 驗證方法
- 新風險
- 待驗證假設
- AI 設定快照
- Skill 版本更新
- AI surface／workflow architecture 變更

### 4. 核心內容
用可跨對話理解的方式說明新增或改變了什麼。

### 5. 證據與確定性
區分：
- 官方或文件支持
- 根據公開資訊合理推論
- 外部觀察
- 尚待驗證
- 教學簡化

### 6. 工作流程影響
說明哪些現行做法受影響、是否需要立即調整、先測試或暫不處理。

### 7. 建議行動
列出可執行的下一步、驗證方式與回退方案。

### 8. 不應覆寫內容
說明現有 canonical、決策或歷史紀錄中不可被這次 Delta 直接取代的部分。

### 9. 尚待確認
只列會影響正式沉澱位置或內容的重要未知。

## 頁面命名

設定與 Skills 快照優先使用：

`[ChatGPT][Config Snapshot] 主題｜YYYY-MM-DD`

一般 Knowledge Delta 使用：

`[ChatGPT][Knowledge Delta] 主題｜YYYY-MM-DD`

若使用者明確要求保存完整交班稿而非 Knowledge Delta，改用：

`[ChatGPT][Handoff｜非 canonical] 主題｜YYYY-MM-DD`

並在頁面開頭明確標示「工作交班暫存，不是正式知識或 canonical」。

## 邊界

- 不把 Notion Link 當成交班全文；下一個 AI 無法存取 Notion 時，仍需提供可貼入的文字。
- 不因找到名稱相似的頁面就假設它是正確目的地。
- 不建立重複頁面；寫入前先搜尋。
- 只更新本次已授權且實際受影響的頁面；依需要可包含一頁或多頁，逐頁回讀並回報結果。
