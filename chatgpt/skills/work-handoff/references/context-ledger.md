# 對話盤點與防遺漏核對

**共通規格：v1.1｜2026-10-21**

維護來源：GitHub 的 `chatgpt/skills/work-handoff/references/context-ledger.md`。thread-handoff、claude-handoff、notion-capture 隨包附帶相同內容，更新時同步；執行只讀本包，不依賴其他 skill 已安裝。

## 1. 確定涵蓋範圍

- 依使用者指定範圍，盤點目前可見的對話、所提供資料與工具已讀取的內容。要求「整個對話」時，涵蓋各重要議題，不自行縮成最後主題。
- 說明實際可見範圍。若只取得摘要、片段或壓縮後上下文，明示限制及可能影響，不宣稱已完整回看，也不從記憶反推逐字稿。
- 先辨識接手／學習目的。盤點可以完整，交班則按下一項工作選取；學習紀錄保留使用者要求範圍內的決策與形成過程。
- 長對話依議題與自然轉折分段，再合併去重。不要猜測 token 使用率，不設最低行數、表格數或嘗試次數。

## 2. 建立一次可重用的內容盤點

對每個重要議題記下已有依據的項目；短任務可合併，不必填空欄。這是內容核對，不是模型的隱藏推理紀錄。

- **問題與目的**：原始問題、預期結果、與其他議題的依賴。
- **事實與證據**：使用者陳述、工具觀察、來源查核、推論／假設分開；保留會改變判斷的數字、日期、版本、識別碼與原文措辭。
- **決策與最後結論**：決定內容、理由、適用範圍及是否已由使用者確認。AI 最後提出的建議、沉默或重複提及，不等於使用者同意。
- **替代方案**：仍在比較、未測試、已否決及否決理由分開。只保留影響理解或後續工作的方案。
- **使用者修正**：尤其保留「不是這個意思」「這部分要保留」等實質修正、範圍限制、格式與術語要求；不要將案內要求自動升格成長期偏好。
- **演變**：原方向 → 可見的新資訊／明確修正 → 現行結論。後來已有明確裁定者沿用新版，舊版標示已取代；未裁定的實質矛盾才列待確認。
- **嘗試與成果**：做法、條件／版本、觀察結果、證據、停止或採用理由、必要時的重試條件。區分未做、執行失敗、完成未驗證、已驗證；未取得資料不能寫成方案無效。
- **授權與限制**：可修改範圍、既有計畫、真正的核准點、不可忽略的專案規則。規劃／審查授權不等於執行授權，保存紀錄不等於核准紀錄內的建議。
- **未完成事項**：未解問題、阻塞、下一步、輸入與完成條件，以及仍在進行或結果不明的外部操作。
- **來源與可存取性**：已讀全文／僅摘要／未取得；URL、檔案路徑、頁面 ID、版本或日期僅填可確認者。區分本次可讀與接手環境是否可讀。

若有前次交班且實際可取得，核對其計畫、決策與現況，補上「自上次交班的變化」；不假設其他討論串可讀，也不為交班建立多餘追蹤系統。

## 3. 產出時保留可接續的資訊

- 完整性優先於縮短篇幅。刪除寒暄與重複，不刪掉會改變理解、判斷、行動或驗收的內容。
- 保留「為什麼」時，只記對話或來源中可見的理由；未說明的理由標示未提供，不補造決策者動機。
- 接手者可取得的完整文件，以確切位置／版本引用並附必要摘要；存取未確認或無法取得時，把開工所需的關鍵內容放入交班稿，並列需補資料。只有連結不等於已交付內容。
- 文字、圖片、試算表及程式各自標示需重新提供的素材；不把文字摘要說成保留了原始附件。
- 排除密碼、金鑰及接續工作不需要的個資；保留必要的非敏感證據與取得方式。
- 多種輸出重用同一盤點，分別核對用途；Notion 學習紀錄不可只從精簡交班稿反推，導致被省略的決策歷程消失。

## 4. 交付前核對

逐項比對盤點與產出，讓每個重要議題都有去處：已納入、引用可取得來源，或因不在本次輸出範圍而省略。不要對使用者省略其明確要求保留的議題。

至少確認：
- 早期／中段的關鍵限制與使用者修正有保留，未只整理最後幾輪。
- 現行結論、已被取代的內容、AI 建議與未決問題沒有混用。
- 決策理由、重要替代方案、嘗試條件和結果未被抽象摘要取代。
- 數字、版本、完成狀態與來源可存取性一致；未知仍標示未知。
- 足以影響主結論或完成判定的反證、失敗、未完成／未驗證事項及已知副作用，已連同最少必要證據與影響放入結論總覽／目前狀態；不能只留在附註或以成功敘述蓋過。使用者已作出的決策保留歸屬，另列反證與影響，不自行改寫為已撤回或改變決策。
- 工具仍待返回、寫入未回讀或結果不明時維持相應狀態，不以舊結果、預期結果或局部成功代替整體完成；不把未驗證直接判為失敗。
- 核對限於本次可見證據與授權範圍；沒有成立問題就如實回報，不製造反證、疑慮或未授權的額外調查。
- 授權範圍與下一步清楚；必要確認沒有遺漏，也未因換接手者重設核准。
- 結果不明的外部操作有標的／可用 ID／回查方式，未安排直接重複寫入。
- 接手者不讀舊對話也能開始指定工作；學習紀錄讀者能理解結論如何形成。

核對在產出過程完成，不必每次附整張檢查表。重要缺漏無法補齊時，明示缺口、影響及取得方式，保留其餘可交付成果。
