# 實作橋接使用範例

本檔是按情境選用的參考。依 SKILL.md 已選模式、實際風險與使用者要求挑選相關段落；沒有相關問題時可明說未發現，不為數量或格式新增問題、產物或核准。

以下分工承接範例中已確認的專案條件；新任務依使用者授權與現行分工選擇，不自動沿用指定工具或核准點。

# 使用範例一｜Proposal Operating System

使用者：

「POS 已經討論得差不多，現在要怎麼實作？」

正確行為：

1. 確認已定案內容：

   * POS／Command Thread
   * 計畫書一 Thread
   * 計畫書二 Thread
   * ChatGPT 負責探索與紅隊
   * Claude 負責正式整合
   * 主持人負責裁定

2. 進行 Design Readiness Check。

3. 建議使用：

   * ChatGPT Project 承載三個 Thread
   * Claude 維護正式主稿
   * Notion 只保存已定案 POS 與 Canonical
   * 不先建立一週作戰板或複雜資料庫

4. 選擇第一個 Pilot：

   * 計畫書一的核心問題與三節點定位

5. 提供逐步操作：

   * 建立 Proposal 1 Thread
   * 貼入 Thread Handoff
   * 與 ChatGPT 討論
   * 主持人標示已定案
   * 使用 Claude Handoff
   * Claude 更新正式主稿
   * Claude 回報差異
   * ChatGPT Review

6. 定義成功：

   * 不需重複解釋背景
   * 正式稿只有一份
   * Claude 可正確更新
   * 主持人可以直接核定修改

不要直接把「建立一週作戰板」當作 POS 實作完成。

# 使用範例二｜AI 人生故事照護流程

使用者：

「人生故事照護模式已討論完成，怎麼放到目前工作流？」

正確行為：

* 確認誰收集故事、誰確認內容、誰使用、資料放哪裡
* 確認是否涉及敏感個資
* 建議先用少數個案 Pilot
* 指定 ChatGPT 協助訪談稿與摘要
* 指定正式紀錄位置
* 指定照護團隊 Review
* 設定病人或代理人同意
* 定義如何驗證故事是否真的進入照護計畫
* 說明如何停止與刪除資料

不要直接建立完整 AI 平台或新資料庫。

---

# 使用範例三｜建立自動化

使用者：

「這個人工流程已經測過，想改成自動化。」

正確行為：

* 確認人工流程已穩定
* 說明哪些步驟可自動化
* 保留人類核准點
* 定義輸入、輸出、錯誤處理與回復
* 程式工作預設由 Claude／Claude Code 承接；使用者指定或既有環境適合時選 Codex／Claude 代理工作（原 Cowork）
* 必要時使用 Claude Handoff
* 先建立測試環境
* 驗證後才正式啟用

不要因為技術可行，就直接全面自動化。
