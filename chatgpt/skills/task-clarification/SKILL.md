# 任務釐清

協助使用者決定真正影響結果的事項，將需求整理成可直接使用的完整任務指令。保留使用者的決定權，資訊足夠就停止追問。

## 適用範圍

只在使用者主動啟用本技能，或明確要求「先釐清需求」「先問重要問題再執行」時採用此流程。一般工作、需求已明確的修改，以及僅引用或討論本技能的內容，不因此進入釐清流程。

## 釐清需求

- 先利用本次對話與使用者提供的資料，可閱讀其提供的附件或指定檔案。已明確的資訊不重問；舊有偏好若可能不適用於本次任務，不直接當成已確認決定。
- 釐清階段可以整理需求、比較選項及草擬任務指令；尚未授權開始正式製作、修改原始檔案或對外操作。額外調查若尚未授權，先列為後續工作，不以釐清為由展開整個任務。
- 優先問會實質改變目標、使用對象、範圍、交付成果、限制或驗收標準的問題，每輪最多 3 題。簡短說明各題答案會影響什麼，不為湊數或填滿清單提問。
- 找出尚未決定的事項、未明說的假設、可能忽略的限制與取捨。把推測標示為待確認，不宣稱知道使用者未說出口的意思。
- 使用者沒有想法時，提出可行選項、主要差異與建議理由，讓使用者決定。低影響且容易調整的細節，可列為建議預設，不逐項追問。
- 區分已知事實、使用者決定、推測與建議。缺少的事實、數據、資源或承諾不可自行補造，也不以看似合理的內容代替證據。

## 停止追問並整理指令

當目標、必要範圍、預期交付及完成判準已清楚，且沒有會實質改變方向的未決事項，就停止追問。任務不涉及的項目不必強行補齊。資料原本已足夠時，直接整理指令，不必先提問。

需要執行時才查證的資料，列入查證工作；不影響方向的缺口，標明即可。涉及重大取捨且尚未獲得使用者決定的事項，仍需先釐清。

整理一份可直接複製使用的完整任務指令，依任務需要納入：

- 目標、必要背景與已確認決定。
- 工作範圍、資料來源及必要查證工作。
- 交付成果、必要格式與限制。
- 可觀察的完成或驗收標準。

另列待確認假設、建議預設及剩餘缺口；沒有就省略。保留原始條件、證據狀態及授權範圍，不增加未同意的工作或承諾。避免為了格式而製造不適用的欄位。

## 確認與交接

請使用者確認或修訂任務指令，並明確表示是否開始執行。在這之前，停留於釐清與指令整理階段；未回覆、單純回答問題或要求修訂，不視為同意執行。

使用者確認指令並授權執行後，結束本技能的釐清階段，依已同意的範圍與驗收標準接續完成原任務。已同意的事項不重複請示；遇到會改變方向或超出範圍的新問題，再提出確認。若使用者只要一份指令，交付指令即完成本次工作。

使用者若明確變更流程、範圍或授權，以本次最新指示為準，不讓本技能的預設流程阻擋已授權的工作。
