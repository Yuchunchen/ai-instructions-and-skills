# Claude Handoff

**版本：v1.6.1｜2026-10-21**

v1.6：Cowork 併入 Claude 介面（組織帳號 2026-11-10 全面切換），僅更新名稱，路由不變。

交付 Claude 可接續的工作脈絡、授權與驗證要求。保留標記 `[ChatGPT-Delta｜for Claude]`，不將第二意見設成所有工作的必經核准。

## 盤點與角色

先讀 [對話盤點與防遺漏核對](references/context-ledger.md)。若本次已有同規格盤點，重用並補新增內容；不得只整理最後幾輪或從精簡摘要反推已遺漏內容。

說明接手的是討論、研究、獨立審查或實作，以及已知的 Claude 介面／環境。目的地已確認時不再詢問。獨立第二意見只授權審查時，不安排修改或發布。

只使用目前可見或已讀取的來源。區分使用者定案、AI 建議、暫定假設、實際完成與未驗證；新版明確修正取代舊結論，未解矛盾才列待確認。不假裝 Claude 能讀舊對話、未提供附件或其他 AI 的記憶。

## 交班內容

依任務合併必要章節，不設篇幅配額：
- **任務與成果**：問題、背景、接手目的、預期產出。
- **目前狀態**：已確認事實、完成成果及驗證、進行中、未開始、受阻及結果不明的操作。
- **決策與演變**：現行決策、理由、重要替代方案與使用者修正；已取代內容標示歷史。
- **嘗試與結果**：做法、條件／版本、觀察結果與停止原因；未試、測試失敗、政策上否決分開。
- **既有授權與邊界**：可修改的文件／程式／頁面、已同意計畫、必要核准點及適用專案規則。
- **Claude 應做與完成條件**：有順序的動作、所需輸入、驗證與具體第一步。
- **來源與重要未知**：實際讀取範圍、確切位置／版本、Claude 是否可取得；不可取得時附開工所需內容與缺口。

保留防 drift 邊界：不重複已完成工作、不將建議升格為決策、不自行擴大範圍或新增不必要的 Agent／Registry／Skill／自動化。使用手機友善 Markdown 與使用者主要語言；中文採繁體中文及台灣用語。

## 接續計畫與授權

要求 handoff plan 或多步工作需說明依賴／驗收時，讀 [接續計畫與接手核對](references/handoff-plan.md)，附可接續計畫；已有計畫就承接剩餘部分。

- 明確修正或唯讀查核：讀必要現況後，直接完成已授權工作與相稱驗證。
- 只有新增範圍、未授權外部動作、不可逆風險或正式權責規定才需新核准；先完成可獨立進行的準備。
- 「不重做」不禁止必要現況核對。外部操作逾時或結果不明時，先回查標的／ID／版本，不直接再次新增或寫入。
- 保留 Dropbox／INDEX.md／CLAUDE.md／SYSTEM.Exec 等適用專案規則，不以交班契約覆蓋它們。
- 接手後回報實際變更、驗證、剩餘問題與必要回復方式；不以交班推定擴權。

## 設定與正式資料

只在涉及 AI 設定／surface／工作流變更時，帶入 Configuration / Surface Delta：
- 變更物件、舊新差異與來源版本。
- 分開標示建議版、Source 已提交、使用者回報已套用、工具／UI 已驗證及 Runtime 未確認。
- 實際受影響的 Architecture／AI surface／Setup Log／instruction snapshot／Skills manifest 等位置，以及最小修改與負責者；未知不補造。
- SOP 留在 Skill，本節不複製完整治理文件。

日常 Notion 維護不因正式頁面身分自動交 Claude。Claude 可在已授權主責範圍內讀取、局部更新並回讀其對應頁面；新接手者先讀最新版。

## Notion 保存與起始指令

只要求交班時不寫 Notion、不執行稿內修改。另要求整理／保存時，使用 `notion-capture`；要求決策、結論與學習歷程則用其「討論決策與學習紀錄」模式，共用完整盤點。明確要求寫入且位置已確認時，完成寫入與回讀，不重複核准同一範圍。

依本次任務改寫 Claude 起始指令：

「請沿用本交班稿的現行決策、授權與計畫，先核對即將使用或修改的必要現況，從指定第一步做到完成條件。不假設可取得未提供資料；審查任務只交付審查結果，未授權不修改。遇到新增範圍、未授權動作、影響方向的重要未知或正式權責規定才回問；結果不明的操作先回查，其他可獨立完成的工作繼續。」

## 可恢復工作狀態

接續既有多步工作時，依 [接續計畫與接手核對](references/handoff-plan.md) 帶入穩定主線／步驟 ID、修訂版、分支父節點與返回點、已採用／已否決／待驗證結果、已驗證成果與未同步操作，以及具體下一步；不讓子題取代剩餘主線。接手先讀現行來源、處理差異，再依授權續作。

整體完成標準列入本次已授權的來源／帳號同步與適用的 Notion 工作狀態更新及回讀，逐項回報成功、失敗或未確認。保存內容不代表 Runtime 已使用；只要交班稿仍不執行稿內工作。

## 完成條件

Be honest in your response. 交付前依共通核對，將足以影響接手判斷或完成狀態的反證、失敗、未完成／未驗證事項及已知副作用，連同證據與影響放進「目前狀態／現行結論」。不為讓交班看起來順利而省略或淡化；交班稿完成仍須如實保留原任務未完成的部分。

按共通規格完成防遺漏核對；Claude 不讀舊對話也能理解背景、決策理由、嘗試結果、範圍、來源與下一步。交班稿完成不表示 Claude 已接收／執行、session 已關閉或系統已更新；外部寫入狀態另列。
